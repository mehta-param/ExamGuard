# Plan 01-02: Pure Graph Coloring Algorithms & Execution Tracing

## Goal
Implement Welsh-Powell Greedy and Recursive Backtracking graph-coloring algorithms in pure Java with complete separation from GUI components, recording an immutable `ExecutionTrace` of step events and achieving 100% test coverage on known graph topologies.

## Requirements Covered
- **REQ-ALGO-01**: Implement Welsh-Powell Greedy graph-coloring heuristic (descending vertex degree ordering + first-fit color assignment).
- **REQ-ALGO-02**: Implement Recursive Backtracking graph-coloring algorithm (exact $k$-coloring decision check and minimum chromatic number $\chi(G)$ finder).
- **REQ-ALGO-03**: Support optional fixed $K$-timeslot feasibility test (determine whether all exams can be scheduled within $K$ slots).
- **REQ-ALGO-04**: Decouple algorithm execution from GUI by recording an immutable `ExecutionTrace` of step events (`TRY_COLOR`, `CONFLICT`, `ASSIGN`, `BACKTRACK`, `FINISH`).

## Architecture & Constraints
- Pure Java in `com.examguard.algorithm`: Zero `javafx.*` imports.
- Pure execution tracing: Algorithms emit step snapshots containing exact explanation text ("Checking vertex CS101..."), which enables downstream Canvas animation in Phase 2 without thread hacks.
- Backtracking includes safety limit (50,000 steps) to prevent runtime freezes on unsolvable/dense inputs.

### Task 2: Welsh-Powell Greedy Algorithm
- **Files**:
  - `src/main/java/com/examguard/algorithm/WelshPowellAlgorithm.java`
- **Actions**:
  - Degree ordering: Sort vertices $v_0 \dots v_{n-1}$ such that $\deg(v_0) \ge \deg(v_1) \ge \dots \ge \deg(v_{n-1})$. If degrees are tied, sort by vertex index for deterministic execution.
  - Step recording:
    - Emit `SELECT_VERTEX` for vertex chosen.
    - Outer loop for colors $c = 1, 2, 3 \dots$:
      - For each uncolored vertex in sorted order:
        - Check if any already-colored neighbor has color $c$.
        - If conflict found: emit `TRY_COLOR`, then `CONFLICT_DETECTED` with conflicting neighbor and student clash explanation.
        - If no conflict: emit `TRY_COLOR`, then `ASSIGN_COLOR` with timeslot $c$.
    - Repeat until all vertices have assigned colors.
    - Emit `FINISH`.
  - Measure execution time using `System.nanoTime()`.
  - Return `ColoringResult` with chromatic count and full `ExecutionTrace`.

### Task 3: Recursive Backtracking Algorithm
- **Files**:
  - `src/main/java/com/examguard/algorithm/BacktrackingAlgorithm.java`
- **Actions**:
  - Recursive search method:
    - `boolean solveKColoring(ConflictGraph graph, int vertexIndex, int k, int[] colorAssignments, ExecutionTrace trace, int[] stepCounter, int maxSteps)`
    - Base case: If `vertexIndex == graph.getVertexCount()`, return `true` (all vertices safely colored).
    - Emit `SELECT_VERTEX` for `vertexIndex`.
    - Loop through candidate colors $c = 1 \dots k$:
      - Check safety: `isSafe(graph, vertexIndex, c, colorAssignments)`.
      - If conflict with neighbor $u$: emit `TRY_COLOR` and `CONFLICT_DETECTED` (specifying $u$ and student clash).
      - If safe:
        - Assign `colorAssignments[vertexIndex] = c`.
        - Emit `ASSIGN_COLOR`.
        - Recurse: `solveKColoring(..., vertexIndex + 1, ...)`.
        - If recursive call returns `true`, return `true`.
        - If false: Backtrack! Reset `colorAssignments[vertexIndex] = 0`, emit `BACKTRACK` with explanation.
    - If no color in $1 \dots k$ works, return `false`.
  - Chromatic number search (`color(ConflictGraph graph)`):
    - Compute Welsh-Powell upper bound $K_{WP}$ on the graph.
    - Test $k = 1, 2, \dots K_{WP}$:
      - Reset step counter and assignments.
      - Call `solveKColoring` with limit $k$.
      - If returns `true`, minimum chromatic number $\chi(G) = k$ is found! Stop search and return result.
  - Fixed $K$-timeslot feasibility (`colorWithLimit(ConflictGraph graph, int maxColors)`):
    - Runs `solveKColoring` directly for $k = maxColors$.
    - Returns `success = true` with assignments if feasible, `success = false` if infeasible.

### Task 4: Unit Testing Algorithms & Trace Verification

- **Actions**:

  - Test 2: Odd cycle graph ($C_5$) colored with 3 colors by both algorithms.

  - Test 4: Conflict verification: assert that for all edges $(u, v)$ in the test graphs, $color(u) \ne color(v)$.
  - Test 5: Trace completeness: assert that `ExecutionTrace` is non-empty, contains `ASSIGN_COLOR` and `FINISH` steps, and step counters increment monotonically.
  - Test 6: Safety limit: verify Backtracking gracefully aborts and returns `success = false` if step limit is exceeded, rather than hanging.
