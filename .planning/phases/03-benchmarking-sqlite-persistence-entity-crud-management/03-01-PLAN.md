# Plan 03-01: SQLite Persistence Layer & Entity CRUD Management

## Goal
Implement the embedded SQLite persistence layer using standard JDBC (`DatabaseManager`), auto-schema initialization, seeding, and the JavaFX Data Management view (`DataManagementView`) providing complete CRUD for subjects, students, and enrollments.

## Requirements Covered
- **REQ-DATA-04**: Local SQLite database persistence using JDBC (`examguard.db`) without JPA/Hibernate overhead.
- **REQ-DATA-02**: Full CRUD management UI (Add, Edit, Delete) for Subjects, Students, and Enrollments.
- **REQ-DATA-01**: Preloaded demo datasets with "Reset to Demo Data" capability.

## Architecture & Constraints
- Pure JDBC with `org.sqlite.JDBC` driver (already in `pom.xml`).
- Direct SQL tables (`subjects`, `students`, `enrollments`) with `ON DELETE CASCADE` foreign keys.
- Auto-seeds default university dataset from `SampleData` if `subjects` table is empty on startup.
- `DataManagementView` built in pure JavaFX (`TableView`, `Dialog`, `CheckBox` list), with zero FXML complexity.
- Live event notification: editing entities or enrollments notifies listeners to refresh the active conflict graph.

## Tasks

### Task 1: SQLite Database Manager & DAO (`com.examguard.db.DatabaseManager`)
- **Files**:
  - `src/main/java/com/examguard/db/DatabaseManager.java`
- **Actions**:
  - Manages SQLite connection with customizable JDBC URL (defaults to `jdbc:sqlite:examguard.db`, supports `jdbc:sqlite::memory:` for headless tests).
  - Initializes schema:
    - `subjects` (`id`, `code` UNIQUE, `name`)
    - `students` (`id`, `name`, `email` UNIQUE)
    - `enrollments` (`student_id`, `subject_id`, PRIMARY KEY, FOREIGN KEYS with CASCADE)
  - Auto-seeds from `SampleData` if database is empty.
  - CRUD Methods:
    - `List<Subject> getAllSubjects()`
    - `Subject insertSubject(String code, String name)`
    - `boolean updateSubject(int id, String code, String name)`
    - `boolean deleteSubject(int id)`
    - `List<Student> getAllStudents()`
    - `Student insertStudent(String name, String email)`
    - `boolean updateStudent(int id, String name, String email)`
    - `boolean deleteStudent(int id)`
    - `List<Enrollment> getAllEnrollments()`
    - `List<Integer> getEnrolledSubjectIds(int studentId)`
    - `void setStudentEnrollments(int studentId, List<Integer> subjectIds)`
    - `void resetToSampleData()`
    - `ConflictGraph loadActiveConflictGraph()`: constructs `ConflictGraph` using current database entities.

### Task 2: Data Management UI View (`com.examguard.ui.DataManagementView`)
- **Files**:
  - `src/main/java/com/examguard/ui/DataManagementView.java`
- **Actions**:
  - Extends `BorderPane` (or `TabPane` with 3 sections):
    - **Subjects Management**:
      - `TableView<Subject>` displaying ID, Code, Name.
      - Buttons: "Add Subject", "Edit Subject", "Delete Subject".
      - Modal dialogs for adding/editing code and name, with input validation (non-empty, unique code).
    - **Students Management**:
      - `TableView<Student>` displaying ID, Name, Email.
      - Buttons: "Add Student", "Edit Student", "Delete Student".
      - Modal dialogs with input validation.
    - **Enrollment Management**:
      - Left: List/table of students.
      - Right: Checkbox list of all subjects.
      - Selecting a student loads their enrolled subjects; toggling any checkbox updates `DatabaseManager` and triggers live graph refresh.
    - **Reset to Demo Data**:
      - Button restoring the default 6-subject 8-student scenario.
  - Listener support: `setOnDataChanged(Runnable callback)` to sync with Canvas and Benchmark tabs.

### Task 3: Unit Tests for Persistence & CRUD (`DatabaseManagerTest.java`)
- **Files**:
  - `src/test/java/com/examguard/db/DatabaseManagerTest.java`
- **Actions**:
  - Uses in-memory SQLite (`jdbc:sqlite::memory:`).
  - Tests schema creation and auto-seeding.
  - Tests CRUD for `Subject` and `Student` (including duplicate constraint handling).
  - Tests `setStudentEnrollments` and CASCADE deletion behavior.
  - Tests `loadActiveConflictGraph()` builds a graph matching database enrollments with 0 false conflicts.
- **Verification**: Run `mvn test -Dtest=DatabaseManagerTest`.
