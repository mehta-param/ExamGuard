# Plan 03-02: Benchmarking Engine, View, Preset Scenarios & Tab Navigation

## Goal
Implement the empirical algorithm benchmarking engine, the side-by-side comparison view (`BenchmarkView`), scenario presets (Small, Medium, Dense), CSV import/export utility, and root `TabPane` navigation in `App.java` connecting all 3 tabs with live data synchronization.

## Requirements Covered
- **REQ-PERF-01**: Side-by-side comparison table between Welsh-Powell Greedy and Recursive Backtracking.
- **REQ-PERF-02**: Empirical comparison metrics (execution time in ms/µs, step count, timeslots used, optimality guarantee).
- **REQ-DATA-01**: Preloaded demo datasets (Small, Medium, Dense/clash-heavy).
- **REQ-DATA-03**: CSV import and export for subjects and enrollments (lightweight file utility).

## Architecture & Constraints
- Pure Java timing using high-precision `System.nanoTime()`.
- Reuses existing pure Java `WelshPowellAlgorithm`, `BacktrackingAlgorithm`, and `ConflictGraph`.
- Root navigation container: `TabPane` in `App.java` hosting:
  - Tab 1: **Timetable & Animation** (`MainView`)
  - Tab 2: **Algorithm Benchmark** (`BenchmarkView`)
  - Tab 3: **Data Management** (`DataManagementView`)
- Live sync: when entities change in Tab 3, Tab 1 and Tab 2 automatically refresh their active conflict graphs.

## Tasks

### Task 1: Benchmark Service & Preset Scenarios (`BenchmarkService.java`, `BenchmarkPresets.java`)
- **Files**:
  - `src/main/java/com/examguard/benchmark/BenchmarkMetric.java`
  - `src/main/java/com/examguard/benchmark/BenchmarkService.java`
  - `src/main/java/com/examguard/benchmark/BenchmarkPresets.java`
- **Actions**:
  - `BenchmarkMetric`: Immutable record/class storing:
    - Algorithm name
    - Execution time (nanos, millis, micros)
    - Total algorithmic steps recorded in `ExecutionTrace`
    - Timeslots (colors) used
    - Conflict-free verification (`schedule.isValid(graph)`)
    - Optimality indicator (Backtracking = Guaranteed Optimal, Welsh-Powell = Polynomial Heuristic)
  - `BenchmarkService`:
    - `Map<String, BenchmarkMetric> runComparison(ConflictGraph graph)`: runs both algorithms on the same graph, capturing timing and trace metrics.
  - `BenchmarkPresets`:
    - Provides 3 standardized comparison datasets:
      1. **Small University Scenario** (6 subjects, 8 students, chromatic number 3).
      2. **Medium Department Scenario** (10 subjects, 18 students, chromatic number 4).
      3. **Dense / Clash-Heavy Scenario** (8 subjects, complete subgraphs $K_4$, demonstrating exponential branching vs fast greedy).

### Task 2: CSV Import/Export Utility (`com.examguard.data.CsvService`)
- **Files**:
  - `src/main/java/com/examguard/data/CsvService.java`
- **Actions**:
  - Pure Java file parsing and formatting (no external dependencies):
    - `exportSubjectsAndEnrollments(File file, List<Subject> subjects, List<Enrollment> enrollments, List<Student> students)`
    - `importSubjectsAndEnrollments(File file, DatabaseManager db)`
  - Safe parsing with error messages for malformed lines.

### Task 3: Benchmark Comparison View (`com.examguard.ui.BenchmarkView`)
- **Files**:
  - `src/main/java/com/examguard/ui/BenchmarkView.java`
- **Actions**:
  - Extends `BorderPane`:
    - **Top Bar**:
      - Scenario Selector (`ComboBox`): ["Active Database Graph", "Small (6 Subjects)", "Medium (10 Subjects)", "Dense / Clash-Heavy (8 Subjects)"].
      - "Run Benchmark" button (`Button`).
    - **Center Content**:
      - **Graph Metrics Header**: Vertices count, Edges count, Max degree, Density score.
      - **Side-by-Side Comparison Grid**:
        - High-contrast cards comparing Welsh-Powell Greedy vs. Recursive Backtracking:
          - Execution Time (formatted in ms and µs).
          - Total Algorithmic Steps recorded.
          - Timeslots Used (colors).
          - Conflict-Free Status ("Zero Conflicts Verified ✓").
          - Optimality Guarantee badge.
          - Winner indicator for speed vs chromatic minimality.
      - **DAA Tradeoff Educational Panel**:
        - Plain-English viva defense summary comparing $O(V^2)$ polynomial greedy heuristic vs $O(m^V)$ exponential exact search.

### Task 4: Root TabPane Navigation Integration (`App.java` & `MainView.java`)
- **Files**:
  - `src/main/java/com/examguard/App.java`
  - `src/main/java/com/examguard/ui/MainView.java`
- **Actions**:
  - Update `App.java`:
    - Instantiates `DatabaseManager` (`examguard.db`), initializing tables and seeding if empty.
    - Creates `TabPane`:
      - Tab 1: "Timetable & Animation" (`MainView`).
      - Tab 2: "Algorithm Benchmark" (`BenchmarkView`).
      - Tab 3: "Data Management" (`DataManagementView`).
    - Wires synchronization: when `DataManagementView` saves changes, calls `mainView.reloadFromDatabase()` and updates `benchmarkView`.
  - Update `MainView.java`:
    - Add `reloadFromDatabase(DatabaseManager db)` to update subject checkboxes, rebuild active conflict graph, and refresh canvas.

### Task 5: Unit Tests for Benchmarking & CSV (`BenchmarkServiceTest.java`, `CsvServiceTest.java`)
