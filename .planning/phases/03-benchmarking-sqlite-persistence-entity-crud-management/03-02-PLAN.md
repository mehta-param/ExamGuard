# Plan 03-02: Benchmarking Engine, View, Preset Scenarios & Tab Navigation

## Goal
Implement the empirical algorithm benchmarking engine, the side-by-side comparison view (`BenchmarkView`), scenario presets (Small, Medium, Dense), and root `TabPane` navigation in `App.java` connecting all 3 tabs with live data synchronization.

## Requirements Covered
- **REQ-PERF-01**: Side-by-side comparison table between Welsh-Powell Greedy and Recursive Backtracking.
- **REQ-PERF-02**: Empirical comparison metrics (execution time in ms/µs, step count, timeslots used, optimality guarantee).
- **REQ-DATA-01**: Preloaded demo datasets (Small, Medium, Dense/clash-heavy).

## Scope Notes (User Approved)
- **Deferred**: `CsvService.java`, CSV import/export, and CSV unit tests are deferred as optional and excluded from this phase.

## Architecture & Constraints
- Pure Java timing using high-precision `System.nanoTime()`.
- Reuses existing pure Java `WelshPowellAlgorithm`, `BacktrackingAlgorithm`, and `ConflictGraph`.
- Both algorithms execute on the **exact same graph instance** for identical metric comparisons.
- Clear Algorithmic Status Distinction:
  - **Proven Minimum (Optimal Chromatic Number)**: Exact optimal $\chi(G)$ guaranteed by completed Backtracking search.
  - **Heuristic Result**: Upper bound generated by Welsh-Powell descending-degree first-fit heuristic.
  - **Interrupted Search**: Warning flag if Backtracking hits safety step counter threshold (50,000 steps).
- Root navigation container: `TabPane` in `App.java` hosting:
  - Tab 1: **Timetable & Animation** (`MainView`)
  - Tab 2: **Algorithm Benchmark** (`BenchmarkView`)
  - Tab 3: **Data Management** (`DataManagementView`)
- Live sync: when entities or enrollments change in Tab 3, Tab 1 and Tab 2 automatically refresh their active conflict graphs and invalidate stale solutions.

## Tasks

### Task 1: Benchmark Service & Preset Scenarios (`BenchmarkService.java`, `BenchmarkPresets.java`)
- **Files**:
  - `src/main/java/com/examguard/benchmark/BenchmarkMetric.java`
  - `src/main/java/com/examguard/benchmark/BenchmarkService.java`
  - `src/main/java/com/examguard/benchmark/BenchmarkPresets.java`
- **Actions**:
  - `BenchmarkMetric`: Immutable class storing:
    - Algorithm name
    - Execution time (nanos, millis, micros)
    - Total algorithmic steps recorded in `ExecutionTrace`
    - Timeslots (colors) used
    - Conflict-free verification (`schedule.isValid(graph)`)
    - Search Outcome Status:
      - `PROVEN_MINIMUM` (Backtracking completed exhaustive search)
      - `HEURISTIC_RESULT` (Welsh-Powell greedy polynomial approximation)
      - `INTERRUPTED_SEARCH` (Backtracking exceeded safety step threshold)
  - `BenchmarkService`:
    - `Map<String, BenchmarkMetric> runComparison(ConflictGraph graph)`: runs both algorithms on the exact same graph, capturing execution timing and trace metrics.
  - `BenchmarkPresets`:
    - Provides 3 standardized comparison datasets:
      1. **Small University Scenario** (6 subjects, 8 students, chromatic number 3).
      2. **Medium Department Scenario** (10 subjects, 18 students, chromatic number 4).
      3. **Dense / Clash-Heavy Scenario** (8 subjects, complete subgraphs $K_4$, demonstrating exponential branching vs fast greedy).

          - Conflict-Free Status ("Zero Conflicts Verified ✓").
